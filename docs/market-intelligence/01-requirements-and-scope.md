# 需求与范围

## 1. 需求依据

市场情报模块直接落实以下需求：

| 需求编号 | 本模块要完成的内容 | 验收重点 |
| --- | --- | --- |
| FR-003 | 展示任务规划、节点、Tool 和结果进度 | SSE 断线后可恢复 |
| FR-004 | 结果分开显示事实、推断和建议 | 关键数字带来源 |
| FR-010 | 查看状态、节点、耗时、重试、结果和错误 | 状态可筛选和查询 |
| FR-011 | 查看节点级 Trace | 能看到 Agent、Tool 和输入输出摘要 |
| FR-012 | 从可恢复节点重新执行失败任务 | 已成功步骤不重复产生副作用 |
| FR-013 | 取消未进入不可中断阶段的任务 | 取消状态持久化 |
| FR-020 | 市场规模、销量或 GMV、增长、价格分布和集中度 | 缺失数据返回 unavailable |
| FR-021 | TOP 竞品和结构化对比 | 关联 platform、product_id 和 source |
| FR-022 | 评论主题、情感、痛点和需求 | 保留样本评论引用 |
| FR-023 | 利润测算和进入约束判断 | 由 Calculator Tool 计算 |
| FR-024 | 生成机会、风险和进入判断 | 关键结论至少关联一个证据 |

## 2. 当前交付范围

当前先完成“市场机会”独立业务模块：

1. 用户在“市场机会”页面填写市场分析需求。
2. 页面通过统一 Agent 任务 API 创建任务。
3. TaskService 把 intent 为 market_entry 的任务交给 MarketIntelligenceService。
4. MarketIntelligenceService 执行 MarketIntelligenceGraph。
5. Graph 调用四个 Tool 获取数据和完成计算。
6. 页面通过 SSE 显示进度，并展示 MarketIntelligenceReport。

当前不修改 SupervisorAgent 和 EcommerceOperationsGraph。

## 3. 市场情报 Agent 的责任

市场情报 Agent负责把已经获得的市场、商品、评论和利润结果整理成报告。它可以：

- 说明样本中出现的价格带、销量展示和商品集中情况。
- 对比竞品的价格、销量、店铺和评论特征。
- 总结评论主题、情感、痛点和需求。
- 引用 ProfitCalculatorTool 的结果判断是否满足最低毛利。
- 输出机会、风险、推断依据和需要补充的数据。

它不能：

- 补造市场规模、GMV、增长率、评论或成本。
- 使用搜索结果样本代表完整市场。
- 绕过 Tool 直接访问数据库、网页或平台 API。
- 生成商品定位、卖点、Listing 或运营诊断结果。
- 执行保存、上架、调价和投放等写操作。

## 4. 数据边界

当前开发、测试和演示统一使用固定版本数据集，不访问淘宝、京东、拼多多等平台页面。

后期真实数据只通过各平台提供的官方 API 接入，并满足以下条件：

- 已取得平台官方 API 文档。
- 已取得合法的应用身份、访问凭据和接口权限。
- 已明确可读取的商品、评论和市场指标范围。
- 已明确分页、限流、重试和数据保存规则。
- 凭据由密钥管理或环境配置提供，不写入代码和数据集。

生产环境只注册已经授权并完成安全检查的 OfficialApiAdapter。平台官方 API 没有提供的数据返回 unavailable。

## 5. 与项目级 AC-01 的关系

需求规格书的 AC-01 包含计划生成、市场和评论数据获取、利润计算、证据化结论以及 Judge。当前模块负责其中的市场情报、数据、利润和证据部分。

完整 AC-01 还需要项目主图中的计划、后续业务节点和最终 Judge。它们属于项目集成范围，不进入本模块开发文档。

## 6. RAG 边界

市场数据、商品数据、评论和利润计算走 Tool 和 Adapter。当前市场机会主链路不使用 RAG。以后如果市场报告需要引用平台政策，调用方可以提供带引用的知识证据，但 RAG 不能代替业务数据查询。
