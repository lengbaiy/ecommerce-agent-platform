# 官方 API 授权与能力确认

## 1. 目的

本文用于确认某个电商平台是否具备接入条件。只有官方文档、应用授权、接口权限和数据使用范围全部明确后，才能注册对应的 `OfficialApiAdapter`。

## 2. 授权信息

接入时应记录以下信息，文档中不得保存真实密钥或 Token。

| 项目 | 必须确认的内容 |
| --- | --- |
| 平台与市场 | 平台名称、站点、国家或地区 |
| 官方文档 | 文档地址、接口版本、确认日期 |
| 应用身份 | 应用类型、Client ID 或 App Key 的配置名称 |
| 授权方式 | OAuth、签名认证或其他官方方式 |
| Token 管理 | 获取、刷新、过期和吊销规则 |
| 权限范围 | 已批准的 Scope、账号和店铺范围 |
| 数据范围 | 自有店铺、授权卖家或公开市场数据 |
| 数据合规 | 保存期限、脱敏要求、审计和删除规则 |

凭据必须按租户和平台隔离，并由密钥管理系统或环境配置提供。日志、Trace、SSE、ToolResponse 和证据摘要不得包含明文凭据。

## 3. 能力确认

能力以实际获批接口为准，并映射到 `AdapterCapabilities`。

| 公共能力 | 需要确认的问题 | Capabilities 字段 |
| --- | --- | --- |
| 商品查询 | 能否按市场、类目和关键词查询商品；是否只覆盖自有商品 | `supports_products`、`max_products` |
| 评论查询 | 能否按商品获取评论；是否包含内容、评分和时间 | `supports_reviews`、`max_reviews_per_product` |
| 市场指标 | 是否直接提供市场规模、GMV、增长或其他聚合指标 | `supports_market_metrics` |
| 排序 | 支持默认、销量或价格排序中的哪些方式 | Adapter 内部排序能力 |

官方接口未提供的能力必须声明为不支持。商品样本统计不能代替全市场指标，Graph 会将缺失能力对应的报告内容标记为 `unavailable` 或生成降级报告。

## 4. 注册条件

满足以下条件后才能注册 `(platform, official_api)`：

- 官方文档版本和接口清单已经确认。
- 平台要求的应用审核、授权或账号准入流程已经完成，所需 Scope 已获批准。
- 租户凭据能够安全加载和刷新。
- `AdapterCapabilities` 与实际权限一致。
- 数据保存和证据留存方式符合平台规则。
- 沙箱或合同测试已经覆盖认证、权限和能力声明。

任一条件缺失时，Adapter 保持未注册，并返回稳定的数据源或授权错误。
