# 官方 API 字段映射与数据口径

## 1. 目的

本文规定平台响应如何转换为市场情报公共 Schema。Mapper 只转换官方响应能够证明的数据，不补写、猜测或由 LLM 推断缺失字段。

## 2. 字段映射表

每个平台实现 Mapper 前，应按以下格式登记字段：

| 官方字段 | 公共字段 | 转换规则 | 缺失处理 | 数据语义 |
| --- | --- | --- | --- | --- |
| 平台商品主键 | `product_id` | 转为非空字符串 | 跳过记录 | 平台稳定商品标识 |
| 商品标题 | `title` | 去除无效空白 | 跳过记录 | 当前商品标题 |
| 商品价格 | `price` | 使用 Decimal | 跳过记录并标记部分结果 | 当前公共契约要求价格必填 |
| 币种 | `currency` | 转为 ISO 货币代码 | 无法确认时跳过记录 | 价格对应币种 |
| 品牌 | `brand` | 空值转为 null | 保留商品 | 官方品牌字段 |
| 类目 | `category` | 映射平台类目名称或 ID | 允许 null | 商品所属类目 |
| 销量原文 | `sales_display` | 保留允许展示的原文 | 允许 null | 数据源展示值 |
| 销量数值 | `sales_value` | 仅在语义可靠时解析 | 设为 null | 精确值、下界、区间或未知 |
| 商品评分 | `rating` | Decimal，保持原评分制说明 | 允许 null | 商品综合评分 |
| 评论数量 | `review_count` | 非负整数 | 允许 null | 必须确认是评论数还是评分数 |
| 店铺或卖家 | `shop_name` | 按平台数据条款和隐私规则保留，必要时脱敏 | 允许 null | 官方店铺字段 |
| 评论主键 | `review_id` | 使用官方 ID 或稳定派生 ID | 跳过记录 | 评论稳定标识 |
| 评论内容 | `content` | 清洗并脱敏 | 跳过记录 | 用户评论正文 |
| 评论时间 | `review_time` | 转为带时区时间 | 允许 null | 评论发布时间 |
| 有用数 | `helpful_count` | 非负整数 | 允许 null | 官方有用投票数 |

实际接入时应把“官方字段”替换为真实字段路径，并记录 Mapper 版本。

## 3. 关键数据口径

### 商品与样本

- SPU、SKU、父商品和子商品的选择规则必须固定，避免重复计数。
- `requested_product_count` 表示请求数量，`actual_product_count` 表示成功映射并进入分析的数量。
- 因必填字段缺失而跳过商品时，CollectionRun 使用 `PARTIAL`，报告保留数据限制。

### 价格与销量

- 金额统一使用 Decimal，不使用浮点数推导业务金额。
- 原币种必须保留；发生汇率转换时记录汇率来源、时间和计算证据。
- `sales_value_type` 只能使用 `exact`、`lower_bound`、`range` 或 `unknown` 的真实语义。
- 评论数、评分数、订单数和销量不能互相替代。

### 时间与市场指标

- 所有时间转换为带时区时间，并保留 `source_timestamp` 和 `ingest_timestamp`。
- 每项 `MarketMetric` 必须带 `AnalysisScope`、统计周期、单位和 `methodology`。
- 商品样本计算结果使用 `sample_` 前缀；官方接口未提供全市场聚合数据时，相应市场指标标记为 `unavailable`。

## 4. 证据与版本

每条标准化数据必须关联 `collection_run_id`、`source_ref`、`source_snapshot_ref` 和 EvidenceReference。允许保存响应时先脱敏并记录 SHA-256；禁止保存完整响应时，只保存官方允许的接口元数据、记录主键、查询范围和哈希。

字段新增或转换修正时升级 Mapper 版本。公共字段语义或类型发生不兼容变化时，按公共 Schema 的大版本规则处理，不能在读取历史数据时静默改写。

## 5. 完成条件

- 商品、评论和市场指标的官方字段均有明确映射。
- 必填字段、缺失处理、去重规则和时间口径已经确定。
- 价格、销量、评论数和市场指标没有语义替代。
- 映射结果能够通过公共 Schema 校验并追溯到官方接口调用。
